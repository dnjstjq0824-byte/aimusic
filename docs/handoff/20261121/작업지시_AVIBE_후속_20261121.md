## WI-N1 Lighthouse 예산 회복 (웹)

**배경**: CI 실측(run 44793175950, mobile, simulate, 1회)

| URL | performance (기준 0.9) | 스크립트 전송량 (기준 174080B) |
|---|---|---|
| `/` | 0.68 | 193,462 |
| `/en/tracks/…` | 0.71 | 204,987 |
| `/th/playlists` | 0.78 | 193,462 |
| `/ja/business` | 0.89 | 197,078 |

Claude가 확인한 원인(홈 리포트 기준):
- FCP 4.6s, LCP 5.4s가 점수를 가장 많이 깎음. TBT 250ms, CLS 0.
- render-blocking CSS `entry.*.css` 약 35KB (예상 절감 1.67s).
- CI의 `nuxt preview`는 **HTML과 `/_i18n/…/messages.json`을 압축하지 않음**(운영은 Cloudflare가 압축). Lighthouse가 압축 미적용으로 약 105KB를 지적.
- 스크립트: 초기 HTML의 modulepreload 외에 하이드레이션 직후 약 13개(약 20KB)가 추가 로드됨. 홈 하단 지연 컴포넌트(트랙 카드·커버 등)와 web-vitals.
- 엔트리 청크(약 52KB br): nuxt + vue-router + vue-i18n(런타임 메시지 컴파일러 포함) + pinia + unhead + SEO 모듈 클라이언트 코드.

**할 일 (측정 → 개선 → 재측정 순서로)**
1. **측정 환경 보정**: CI preview에서 동적 응답(HTML, messages.json)도 압축되게 합니다(예: Nitro 플러그인으로 `NUXT_COMPRESS_PUBLIC_ASSETS=1`일 때만 gzip/br). 운영 이미지 동작은 바꾸지 않습니다. `numberOfRuns`를 3으로 올려 중앙값으로 판정합니다.
2. **CSS**: 첫 화면 렌더를 막는 CSS를 줄입니다(사용하지 않는 유틸리티 정리, 첫 화면 필수 CSS 인라인 등). 방법은 자유이고, 결과로 증명합니다.
3. **하단 컴포넌트**: 홈 하단 섹션을 화면에 보일 때 하이드레이션하도록 바꿉니다(Nuxt 지연 하이드레이션 기능 사용 가능 여부를 현재 Nuxt 버전에서 확인 후 적용).
4. **엔트리**: `npx nuxi analyze`로 모듈별 크기를 기록하고, 클라이언트에서 불필요한 SEO 모듈 코드(nuxt-schema-org, nuxt-og-image, nuxt-site-config)의 클라이언트 런타임을 끌 수 있는지 확인합니다. vue-i18n 런타임 컴파일러는 메시지가 실행 중 문자열로 들어오므로 **그냥 빼면 번역이 깨집니다**. 메시지를 빌드 시 컴파일하는 방식으로 바꿀 수 있을 때만 제거합니다.
5. LCP 요소(홈 히어로)의 이미지·폰트 로딩 우선순위 점검.
6. 전부 충족하면 `web/lighthouserc.cjs`의 performance와 `resource-summary:script:size`를 `error`로 되돌립니다.

**수용 기준**
- CI에서 4개 URL 모두 performance ≥ 0.9, 스크립트 ≤ 174080B를 **연속 2회** 통과.
- `lighthouserc.cjs` assertion이 `error`로 복구됨.
- 기능 회귀 없음: 검증 기본 세트, E2E 전수, 하네스 통과. 콘솔 언어 전환(en/ja/th/zh-cn)에서 번역 키 노출 0.
- 진행로그에 항목별 전후 수치(KB, 점수)를 남김.

**배경**: G2(모델 실측)는 GPU가 없어 `NOT TESTED`입니다. `generator/README.md` 기준 ACE-Step급 모델은 CUDA GPU와 VRAM 8GB 이상이 필요합니다. 일반 VPS(GPU 없음)와 집 PC(GTX 1630 4GB)로는 실측할 수 없습니다. 운영 VPS에는 `GENERATION_BACKEND_URL`이 설정돼 있지 않습니다.

**할 일**
1. `generator/server.py`를 서버리스 GPU(`docs/generation/gpu-options.md`의 후보 C1~C3)에 올리는 배포 레시피 작성(컨테이너 이미지, 가중치 로딩, 헬스체크, 콜드스타트 대응). 공급사별 차이는 표로 정리.
2. `run_poc.py`와 `eval/` 스크립트가 원격 엔드포인트를 대상으로 돌도록 인자화.
3. 가격 칸은 비워 둡니다(실측·견적 전 숫자 금지).

**수용 기준**
- 로컬에서 모의(가짜 infer) 엔드포인트로 워커 → 생성 서버 v2 계약 왕복 테스트 통과.
- 공급사 가입·결제·실측은 P6 이후. 운영 연결(`GENERATION_BACKEND_URL`)은 G-MODEL 통과 후.
