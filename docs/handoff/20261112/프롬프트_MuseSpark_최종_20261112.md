```

대기 해제. 아래 문서를 순서대로 읽어라.
docs/handoff/20261112/

먼저 알아둘 것:
- 감사 1차 조치는 이미 끝나서 운영에 반영됐다(작업지시서 §1 표). 그 항목은 다시 하지 마라.
  코드는 audit-fixes-20261112 브랜치(PR #1)에 있다.
- 역할: 너는 엔진과 화면(web/, mobile/)을 모두 구현한다.
- 이번 일의 최우선은 WI-D1 R2 이전이다. R2 이전이 끝나면 Cloudflare Access 작업은 필요 없다.
- 환불 정책은 확정됐다(작업지시서 §1). 바꾸지 마라.

이번 단계에서 할 일은 WI-D0 현황 보고뿐이다. 코드는 한 줄도 바꾸지 마라.
보고에 넣을 것:
1. 현재 브랜치, HEAD 커밋, PR #1 병합 여부, 미커밋 변경 수
2. 운영 VPS 읽기 전용 확인: docker ps, schema_migrations 최신 버전, .env의 S3_ENDPOINT·S3_PUBLIC_ENDPOINT 값(비밀값 제외), /opt/avibe/backups 최근 파일, crontab -l

4. R2 이전에 PO가 준비해야 할 것 목록(버킷 이름, API 토큰 권한 범위 등)
5. 항목별 예상 변경 파일 수. 합계가 50개를 넘으면 무엇을 3차로 넘길지 제안

지켜야 할 것:
- 운영에 쓰는 작업(DB 쓰기, 객체 삭제, 컨테이너 재시작, 터널·Worker 배포)은 내 승인 없이 하지 마라.
- 실결제·실환불 금지. 비밀값을 저장소·로그·보고서에 남기지 마라.
- 보고 후 내 착수 승인이 올 때까지 대기.
```

## 2번 — WI-D0 보고를 확인한 뒤 보낼 것 (착수 승인)

PO 확인 사항: R2 전환 방식, 준비물 목록, 50개 상한 재산정. R2 API 토큰을 VPS `.env`에 넣은 뒤에 보낸다.

```
[PO 착수 승인 — WI-D0 보고 확인 완료]

작업지시_AVIBE_최종_20261112.md의 착수를 승인한다.
R2 전환 방식: (a 또는 b를 적는다)
R2 준비 완료: 버킷 2개 생성, API 토큰을 VPS .env에 반영함.
(3차로 넘기는 항목이 있으면 여기에 적는다)

순서: WI-D1 → WI-D2 → WI-D3 → WI-D6 → WI-D4 → WI-D5 → WI-D7 → WI-D8(삭제 목록 보고까지만).

규칙:
- 항목마다 별도 커밋, 커밋 메시지에 WI-Dx.
- 예상 파일 수를 넘길 것 같으면 커밋 전에 멈추고 보고.
- WI-D1은 객체 복사 대조표를 먼저 보고하고 내 확인 후에 서버·Worker를 전환해라(G-R2).
- 운영 배포 전에는 /opt/avibe/backup-db.sh로 백업을 1회 더 받고, 롤백 경로를 함께 보고해라.
- 약관은 수정안만 쓰고 게시하지 마라.

완료 보고는 지시서 §5 형식으로 하고, 수용 체크리스트(C-0~C-9) 항목별 PASS/FAIL/BLOCKED/NOT TESTED와 증거를 붙여라.
증거 없는 PASS는 반려한다.
```
