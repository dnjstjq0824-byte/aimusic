### WI-D1. 음원 저장소 R2 이전 (최우선, 예상 8~12개)
- 근거: O-01 잔여, S-01 잔여. 지금 음원은 VPS의 LocalStack에 있다. LocalStack은 테스트용이라 S3 서명을 검증하지 않는다. 현재는 터널 경로 허용목록으로만 막고 있고, HLS 파일은 서명 없이 직접 받을 수 있다.
- PO가 Cloudflare R2 무료 플랜을 개설했다. R2 API 토큰(버킷 읽기·쓰기)은 PO가 발급해 VPS `.env`에 넣는다. 토큰 값은 저장소·로그·보고서에 남기지 않는다.
- 목표 구조:
  1. **버킷 2개(비공개):** 원본 마스터용 staging, 변환 결과용 hls. 퍼블릭 액세스는 끈다.
  2. **서버:** `STORAGE_DRIVER=r2`(이미 `backend/internal/pkg/storage/storage.go` NewFromEnv에 있음)로 API·워커가 R2 S3 API를 쓴다. 브라우저 업로드용 presigned PUT도 R2 엔드포인트로 발급한다. R2는 서명을 검증하므로 공개돼도 안전하다.
  3. **staging 버킷 CORS:** `https://avibemusic.com`의 PUT만 허용한다.
  4. **Worker:** `/local-hls/` 요청을 R2 바인딩(`[[r2_buckets]]`)으로 직접 읽는다. 현재의 서명 검사(q 등급 포함)는 그대로 유지한다. `S3_ORIGIN` 경유 fetch와 Access 토큰 코드는 R2 전환 후 제거한다.
  5. **데이터 이전:** LocalStack의 기존 객체(약 65MB)를 같은 키로 R2에 복사한다. 키 목록과 크기를 대조해 보고한다.
  6. **정리:** 전환 확인 후 터널에서 `hls.avibemusic.com` 규칙을 제거하고 LocalStack 컨테이너를 내린다. 데이터 볼륨은 PO 승인 전까지 지우지 않는다.
- 전환 순서는 둘 중 하나를 고른다: (a) 복사 → 서버 전환 → Worker 전환 → 검증 → 정리, 또는 (b) 잠깐 업로드를 막는 유지보수 창. 어느 쪽인지와 이유를 WI-D0 보고에 적는다.
- 검증(전환 후 운영):
  - 재생: 로그인 사용자 SQ, 이용권 사용자 HQ
  - 파트너 업로드 → 변환 → 재생
  - 다운로드
  - 관리자 DSP 마스터 링크
  - 임시조치 시 HLS 삭제
  - `hls.avibemusic.com` 전 경로 404
- **이 항목이 끝나면 Cloudflare Access 작업은 필요 없다.** 하지 않는다.

## 4. 가드레일과 게이트

**가드레일 (위반 시 반려)**
1. 전체 변경 파일 상한은 **50개**다(WI-D8 제외 여부는 PO가 판단). 넘을 것 같으면 커밋 전에 멈추고 보고한다.
2. 항목마다 커밋을 나누고, 커밋 메시지에 항목 번호(WI-Dx)를 넣는다.
3. 지시서에 없는 파일을 수정했으면 별도 커밋으로 분리하고 사유를 적는다.
4. **운영 데이터에 쓰는 작업**(DB 쓰기, 객체 삭제, 컨테이너 재시작, 터널·Worker 배포)은 항목별 PO 승인 후에만 한다.
5. 실결제·실환불을 하지 않는다. Toss는 테스트 키와 목 서버로만 검증한다.
6. 비밀값(R2 토큰, Toss 키, JWT 키)을 저장소·로그·보고서에 남기지 않는다.
7. 화면 변경은 1440px·390px 전후 캡처를 첨부한다.

**게이트**
- **G-2 (운영 배포):** 항목별 PO 승인. 배포 전 `/opt/avibe/backup-db.sh`로 백업을 1회 더 받는다. 배포는 `deploy/rollout-20261112.sh`의 순서(Worker → 백엔드 → 검증)를 따르고, 롤백 경로를 함께 보고한다.
- **G-3 (약관 게시):** 법률 확인 후 PO 승인.
- **G-R2 (저장소 전환):** WI-D1의 서버 전환과 Worker 전환은 데이터 복사 대조 결과를 PO가 확인한 뒤에 한다. LocalStack 볼륨 삭제는 별도 승인이 필요하다.
