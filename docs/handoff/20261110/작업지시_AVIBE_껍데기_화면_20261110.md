# 작업지시서 — AVIBE 껍데기(화면) v2.1 (2026-11-10 개정 — 전 너비 재조사 반영)

| 항목 | 내용 |
|---|---|
| 대상 | avibemusic.com 웹 프론트 (화면·문구·표기·동선 표시) |
| 수신 | 화면 작업 담당 에이전트 (지정 즉시 착수 가능하게 작성됨) |
| 발행 | Muse (기획·검증) — 근거: 종합검토 보고서, 방향결정서, 약관 초안, 클릭 프로브 검수 기록 |
| 범위 밖 | 내부 엔진(백엔드·API·정산)은 Spark 세션 소관 — 엔진 파일 수정 금지 |
| 전제 조건 | 여정 차단(P0)의 원인은 엔진 API 서버 오류다. 화면 항목 중 상태 표시에 관한 것만 이 지시로 고치고, 동선 복구 자체는 엔진 WI-01 완료가 전제다. 전제가 안 된 항목은 BLOCKED로 보고한다 |
| 상태 | **이 지시서 전달 ≠ 착수 승인.** PO가 착수를 명시한 뒤에 시작한다. 클릭 프로브 결함 20건 + 미구현 확인분 + 전 너비 재조사(2026-11-10 16:12) 결함 5건을 전건 반영한 개정판이다 |

## 1. 전제 (기획 측 확정 — 임의로 바꾸지 않는다)
1. 문구·표기의 정본은 방향결정서와 약관 초안이다. 화면 표시가 문서와 다르면 문서가 맞다.
2. 인증 문구는 전 표면 **"상업적 이용권 보유 인증"** 으로 통일한다.
3. 가격표 정본은 보고서 7-1이다 (매장 9,900·14,900 / 라이선스 19,900·29,900 / 생성 구독 9,900).
4. 사업자는 미신고 상태다 — 사업자 표시는 코드만 완성하고 숨긴다 (SC-04).

## 2. 작업 항목

### SC-01. 문구 정비 (예상 3개)
- 홈페이지·푸터·탐색 화면의 단정 표현("100% 검증", "100% 상업 이용 가능", "100% AI 투명성" 등)을 사실 표현으로 교체한다. 예: "4단계 인증을 통과한 음원만 유통합니다".
- 선행 확인: 엔진 세션 검토에서 **작업 트리 소스에는 이미 0건**으로 보고됐다. 착수 시 전수 grep으로 잔존을 먼저 확인하고, 잔존이 없으면 이 항목은 "소스 완료·배포 대기"로 보고만 한다 (없는 작업을 만들지 않는다).
- 통계 표기("568 검증 음원", "1.1M+ 총 감상" 등)는 실데이터 연동이 안 되면 지운다. 지어낸 숫자를 화면에 두지 않는다.

### SC-02. 도메인·링크 표기 통일 (예상 2개)
- canonical·OG·내부 링크의 도메인 표기를 avibemusic.com으로 통일한다 (web/index.html 포함, 엔진 지시 WI-03에서 제외된 화면 몫).
- AI 저작권 정책 링크 주소 불일치(AI_COPYRIGHT_POLICY → COPYRIGHT_POLICY 이동)를 정정한다.

### SC-03. 약관·정책 화면 (예상 6개) — 게이트 G-3 연동
- 약관 4종(이용약관·개인정보처리방침·AI 저작권 정책·파트너 계약서) 페이지가 본문을 정상 표시하는 구조를 만든다. 현재는 링크만 있고 전부 서버 오류다 (원인은 엔진 API라, 화면은 "받아서 보여주는 구조"까지가 완료).
- 시행 전인 약관 판은 본문과 분리해 **"공지 중"** 으로 표시한다 (시행일·공지 시작일을 함께).
- 약관 본문의 **실제 게시는 법률 검토 후 PO 승인**으로 한다 (게이트 G-3). 그 전까지는 초안 본문을 내부 확인용으로만 연결한다.

### SC-04. 사업자 표시 블록 (예상 2개)
- 푸터 사업자 표시 블록은 코드로 완성하되, 값(VITE_BUSINESS_*)이 비어 있으면 **블록 자체가 렌더링되지 않게** 한다. 라벨만 남거나 빈 칸이 보이면 불합격이다.
- 신고 완료 후 값 입력만으로 표시가 켜지는 것을 로컬에서 값 유무 양쪽으로 확인해 보고한다.

### SC-05. 요금제 화면 (예상 3개)
- 플랜 표기를 정본과 일치시킨다: FREE / 생성 구독 9,900원 / 매장 9,900·14,900원 / 라이선스 19,900·29,900원.
- "1개월 단기 패스·자동결제 없음·결제 후 7일 이내 미사용 시 전액 환불" 표기를 약관 제7·8조와 글자 단위로 일치시킨다.
- B2B 정기결제는 Phase 2 결정 사항이다 — 지금 화면에 정기결제를 표기하지 않는다.

### SC-06. 인증 문구 통일 (예상 4개)
- 파트너 스튜디오·권리보호센터·업로드 화면의 인증 관련 문구를 "상업적 이용권 보유 인증"으로 통일한다.
- "보장"이라는 단어가 권리·검증 맥락에서 쓰인 곳은 전수 grep해 교체 목록을 보고에 첨부한다.

### SC-07. 오류·빈 상태 표시 분리 (예상 3개) — 프로브 결함 12·13
- 데이터가 진짜 0건인 빈 상태와, 로드에 실패한 오류 상태를 화면에서 구분한다. 빈 상태인데 오류 알림이 함께 뜨는 현재 상태를 고친다 (탐색·홈).
- 같은 오류 알림이 2개 겹쳐 쌓이지 않게 한다 (로그인 실패 시 중복 표시 확인됨).
- '다시 시도' 버튼은 눌렀을 때 진행 중 표시와 결과(복구/재실패)를 화면에서 알 수 있게 한다. 현재는 눌러도 뭐가 일어났는지 알 수 없다.

### SC-08. 플레이어 보강 (예상 5개) — 프로브 결함 19·20 + 미구현 확인
- 현재 없음으로 확인된 **볼륨 조절, 전체(확장) 플레이어 전환, 플레이어 닫기**를 신설한다.
- 아이콘만 있는 버튼 7종(셔플·이전·재생·다음·반복·대기열 등)에 툴팁 또는 텍스트 라벨을 붙인다. 셔플·반복 상태는 색만이 아니라 텍스트로도 표시한다.
- 재생할 수 없는 상태(곡 없음·로드 실패)에서 재생 관련 버튼을 누르면 이유를 알리는 피드백을 준다. '전체 셔플 재생'의 무반응을 고친다.
- 재생 토글 상태가 페이지 이동 후 초기화되는 현상을 확인하고, 유지가 기획 의도와 다르면 보고한다 (임의 결정 금지).

### SC-09. 푸터·링크 목적지 정정 (예상 3개) — 프로브 결함 7·8·10
- '실시간 Top 음원' 링크가 홈이 아닌 실제 차트(탐색의 인기순 등 맞는 목적지)로 가게 한다. 맞는 목적지가 없으면 링크 문구를 실제 목적지에 맞게 바꾼다.
- 'AI 모델별 탐색' 링크에 해당 모델 필터가 적용된 상태로 탐색이 열리게 한다.
- '상세 필터 →' 버튼이 필터를 열지 않고 '전체 탐색 →'와 같은 페이지로만 이동한다 — 필터 패널이 열리는 동작으로 바꾸거나 버튼 문구를 실제 동작에 맞춘다.
- 고정 플레이어 바가 푸터 최하단(저작권 표기·법 준수 배지)을 가리는 문제를 고친다 — 본문 하단 여백 확보 등 방식은 구현 측이 정하되, 전 페이지에서 푸터 끝까지 보이는 것이 완료 조건이다. **전 너비 공통 결함**이며 모바일(390)에서는 플레이어가 2단으로 더 높아 가림이 더 크다.

### SC-10. 가입·로그인 화면 정비 (예상 4개) — 프로브 결함 11 + 동의 분리
- 유효성 오류(이메일 형식·비밀번호 길이 등)를 화면 문구로 표시한다. 현재는 문구 없이 제출 버튼만 비활성화된다.
- 비활성 버튼을 활성 버튼과 구분되는 스타일로 바꾼다 (현재 같은 색이라 눌리는 줄 안다).
- **약관 동의와 개인정보 수집·이용 동의를 각각의 체크로 분리한다.** 현재는 묶음 체크 1개뿐이다 — 법적 분리 요건이라 생략 불가. 각 동의 옆에 해당 문서로 가는 링크를 둔다.
- 가입 유형(리스너/파트너)은 현행 탭 구조를 유지한다. 별도 가입 페이지를 새로 만들지는 않는다 (기획 결정).
- 모바일(430 이하) 헤더에 회원가입 버튼이 없어 가입 진입이 로그인 페이지 탭뿐이다 — 헤더 진입을 유지할지 기획 확인을 받아 결정하고, 임의로 없애지 않는다.

### SC-11. 빈 공간·겹침·플레이스홀더 (예상 6개) — 프로브 결함 15·16·17·18 + 재조사 결함
- 요금제·홈 카드 행의 불균형한 빈 공간(한쪽만 차고 반대쪽이 텅 빔)을 그리드 기준으로 정비한다. 단, 유료 플랜이 안 떠서 생긴 빈 공간은 엔진 복구가 전제라 BLOCKED로 구분한다.
- 404 페이지: '404'와 'NOT FOUND' 글자 겹침을 고치고, 상단 메뉴·푸터를 다른 페이지와 동일하게 붙인다 (현재 두 버튼 외 이동 수단 없음).
- 바로 듣기 카드의 커버 플레이스홀더(그라데이션+♪)는 실제 커버가 없을 때의 표시 규칙으로 명시한다 — 실제 서비스처럼 보이게 지어내지 않는다.
- 홈 검색 버튼 아이콘을 돋보기로 교체한다 (현재 위쪽 화살표라 검색인지 알기 어렵다).
- 홈 카드 행 잘림에 스크롤 힌트를 준다: 834·768에서는 5번째 카드가, 430·390·360에서는 3번째 카드부터 가장자리에서 잘리는데 가로 스크롤이 가능한지 알 방법이 없다 (화살표·페이드·스크롤바 중 하나로 표시).
- 모바일(430 이하)에서 오류 토스트가 카드 제목·설명과 결과 영역을 가리지 않게 위치·자동 소멸을 정비한다. 360px에서 플레이어 부제("원하는 음원을 선택하세요")가 말줄임으로 잘리는 것도 함께 고친다.

### SC-12. 미구현 항목 — 기획 결정 대기 (작업 금지, 보고만)
프로브에서 없음으로 확인된 것 중 아래는 만들지 말지부터 기획 결정이 필요한 것들이다. 임의로 만들지 말고, 착수 보고에 "결정 대기"로 남긴다.
- 소셜 로그인 (구글·카카오)
- 이어듣기 영역
- 좋아요·공유·더보기·알림·설정 아이콘류

### SC-13. 반응형 전수 확인 (변경 0 — 검증 항목)
- 기획 측 재조사(2026-11-10 16:12)로 너비 8종(1440·1280·1024·834·768·430·390·360)의 실렌더 확인은 끝났다 — 햄버거 전환 경계 1024px, 페이지 전체 가로 넘침 없음, 필터 접힘 정상. 발견된 너비 결함은 SC-09·SC-10·SC-11에 반영했다.
- 단, 요금제 **유료 카드 행의 너비별 접힘은 서버 오류로 아직 미확인**이다 — 엔진 복구 후 기획 측이 재확인한다.
- 집행 완료 보고에는 너비 9종(1920 포함) × 주요 화면(홈·탐색·로그인/가입·요금제·플레이어)의 캡처가 전부 있어야 한다. 경계 너비에서 버튼 잘림·겹침·가로 넘침·메뉴 전환을 확인한 기록이 없으면 완료로 받지 않는다.

**항목별 예상 합계 41개, 전체 상한 45개.** (SC-12는 작업 0, SC-13은 검증만) 상한을 넘길 것 같으면 커밋 전에 멈추고 보고한다.

## 3. 변경 범위 가드레일 (전 항목 공통, 위반 시 반려)
1. 항목별 예상 파일 수 초과가 보이면 커밋 전에 멈추고 변경 목록부터 보고한다.
2. 전체 상한 45개 초과가 불가피하면 작업을 나눠 후속 지시로 분리 제안한다.
3. 지시서에 없는 파일을 고쳤으면 별도 커밋으로 분리하고 사유를 적는다.
4. 빌드 산출물·생성 파일은 커밋하지 않는다 (.gitignore 점검 포함).
5. 완료 보고에 `git diff --stat` 기준 전체 변경 파일 목록 + 파일별 대응 항목 번호(SC-xx) 매핑표를 첨부한다.
6. 신규 생성 파일과 삭제 파일은 수정과 구분해 별도로 센다.

## 4. 수용 기준 (화면 작업은 렌더 실측으로만 판정한다)
- A-S1: 각 항목 완료 시 **데스크톱(1920)과 모바일(390) 캡처**를 증거로 첨부한다. 코드 대조만으로 완료 보고 금지. 전 너비는 SC-13 기준.
- A-S2: "100%"·"보장" grep 결과가 문구 교체 목록과 일치한다.
- A-S3: 사업자 블록은 값 없음=미표시, 값 있음=표시를 양쪽 캡처로 확인한다.
- A-S4: 약관 4종 페이지가 (엔진 복구 후) 본문을 표시하고, 공지 중 판이 분리 표시된다. 엔진 미복구 상태에서는 BLOCKED로 표기한다.
- A-S5: 여정 6종(청취자·가입자·구매자·파트너·권리자·공통 상태)을 직접 걸어본 기록을 첨부한다. 엔진 전제가 안 된 여정은 BLOCKED 사유를 명시한다.
- A-S6: 빈 상태와 오류 상태가 화면에서 구분되고, 오류 알림이 중복으로 쌓이지 않는다.

## 5. 완료 보고 형식
항목별 상태(PASS/FAIL/BLOCKED/NOT TESTED) · 변경 파일 매핑표 · 캡처 증거 · 잔존 결함. 증거 없는 완료 주장은 반려한다.
