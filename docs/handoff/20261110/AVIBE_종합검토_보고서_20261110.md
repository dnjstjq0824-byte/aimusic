## 0. 결론 요약 (먼저 이것만)

**판정: 지금 형태(일반인 스트리밍 + 월간 이용권)로는 사업성 없음. 아래 통합안으로 전환하면 조건부로 사업성이 생긴다.**

통합안 한 줄: **우리가 직접 카탈로그를 만드는 유통사가 되고, 그 카탈로그를 ① 매장 BGM 구독과 ② 영상 라이선스 구독 두 문으로 팔고, 번 돈의 절반을 실제 사용 비율로 창작자에게 나눈다. 일반인 스트리밍은 공짜 전시장으로만 둔다.**

핵심 근거 5개:
1. 지금 서비스는 손님을 받을 수 있는 상태가 아니다 — 음원을 불러오는 서버가 꺼져 있고, 곡이 0곡, 결제도 연결이 안 돼 있다 (1장 실측).
2. 일반 청취자는 AI 곡에 돈을 안 낸다 — 전 세계 실측으로 AI 곡은 재생의 1~3%, 이용자 45%는 AI 곡을 아예 걸러내길 원한다.
3. 반대로 매장 사장과 영상 제작자는 지금도 매달 음악 이용료를 내고 있고, "저작권료 걱정 없음"에 돈을 낼 이유가 분명하다.
4. Suno처럼 손님이 누를 때마다 생성하는 사업은 적자 구조지만, **크레딧으로 한 번에 재고를 쌓고 생성 서버를 지우는 방식**은 적자가 쌓이지 않는다. 구글 크레딧 40만원으로 시작 가능하나, 체험 크레딧은 GPU가 잠겨 있어 유료 전환이 먼저다 (4장).
5. 법적으로 제일 위험한 것은 기술이 아니라 문구다 — "상업 라이선스 100% 검증·보장"은 지금 검증 범위로는 지킬 수 없는 약속이라, 표시·광고 규제와 분쟁 책임이 그대로 돌아온다. 문구를 검증 실체에 맞게 줄이는 게 1순위 법적 조치다 (5장).

**당장 돈과 시간을 쓸 순서:** 서버·결제 정상화 → 생성 파이프라인 구축(크레딧 소진 전) → 카탈로그 500곡 → 매장 파일럿 30곳 → 전환율 보고 확대/중단 판정. 총 검증 기간 90일, 이 기간의 목적은 매출이 아니라 "팔리는가"의 증거 확보다.

## 2. 사업 방향 판정표

| 방향 | 판정 | 이유 |
|---|---|---|
| A. 일반인 스트리밍 + 월 이용권 (현행) | 🔴 중단 | 수요 실측이 없다 (AI 곡 재생 1~3%). 무료 전 곡 제공과 유료 판매가 서로를 죽임 |
| B. Suno형 생성 서비스 (손님이 직접 생성) | 🔴 안 함 | 생성할 때마다 연산비, 음반사와 라이선스 전쟁 중, 자본 체급 싸움. 사용자 판정과 동일 |
| C. 매장 BGM 구독 | ✅ 1순위 | 매장은 이미 월 2만~3만원을 내는 시장. 음저협 미등록 AI 곡은 공연권료 대상이 아니라는 차별점. 국내 선행 사례(에또뮤직 월 6,000원)가 수요를 증명 |
| D. 영상 라이선스 구독 | ✅ 2순위 | 저작권 경고 공포가 구매 이유. 곡별 검증 인증서 + 분쟁 소명 대행이 상품. 해외 기준가 월 $10~25 형성됨 |
| E. 자체 카탈로그 유통사 (공급 엔진) | ✅ 채택 | 크레딧으로 일회성 생산 → 서버 삭제. 재고는 남고 적자는 안 쌓임. C·D의 "곡 0곡" 문제를 동시에 해결 |
| F. 주문 제작 중개 (로고송·CM송) | ⚠️ 보조 | 건당 30만~300만원, 수수료 30%. 물량이 적어 본업은 못 되지만 마진이 좋고 검증 게이트가 입점 자격이 됨 |
| G. 검증 기술 API 판매 | ⚠️ 후순위 | 남의 플랫폼에 검사를 파는 일. 우리 카탈로그·고객이 쌓인 뒤에나 팔린다 |

**최종 구조 = E(공급) + C·D(판매) + F(보조).** 아래 3~8장은 전부 이 구조 기준이다.

## 3. 도입해야 할 것 — 기술·시스템

### 3-1. 인프라 정상화 [최우선, 모든 것의 선행]
- 임시 터널 제거 → 정식 서버 1대 + 도메인 연결. 지금의 530 오류는 "서버 프로그램이 임시 주소 뒤에 숨어 있던" 구조라 주소가 바뀌면 통째로 끊긴다.
- 대표 도메인 통일: avibemusic.com으로 확정하고 avibe.kr은 사서(또는 보유 시) 자동 연결(리다이렉트). 사이트 정보 속 공식 주소 표기도 하나로 수정.
- 결제 연결: 토스 결제 키 발급·등록, 요금제 데이터 정상화, 환불 규정(7일 미사용 전액 환불 — 이미 약관 문구에 있음) 실제 동작 확인.
- 백업·감시: 서버가 죽으면 알림이 오는 감시 1개만이라도. 지금처럼 "사용자가 안 들어간다고 말해줘서 아는" 상태가 되면 안 된다.

### 3-2. 생성 엔진 (유통사 공급 라인)
- **주 엔진 ACE-Step (v1 Apache 2.0 / 1.5 MIT)** — 배경음악 대량 생산. 곡당 수십 초, 사용 가능한 곡 1개당 비용 1센트 미만 수준.
- **보조 엔진 HeartMuLa (Apache 2.0)** — 보컬·고품질 곡용. 느리고 무겁지만(그래픽 메모리 16~24GB) 한국어 포함 다국어 보컬이 강점.
- 금지 목록을 코드에 박을 것: MusicGen(가중치 비상업), YuE2(비상업), Tencent LeVo(비상업). "무료 오픈소스"라는 말만 믿고 넣으면 카탈로그 전체가 판매 불가품이 된다 (상세 표는 5-4).
- 생성 기록 의무화: 곡마다 모델명·버전·라이선스·프롬프트·생성일·파일 지문(SHA-256)을 자동 저장. 이 기록이 나중에 "이 곡은 합법 재료로 만들었다"는 유일한 증거다. AVIBE 기존 검증 게이트의 입력값을 우리 생성 쪽에도 그대로 적용하는 셈이다.
- 구글 크레딧 사용 절차 (4장에서 비용 계산):
  1. 크레딧 종류·만료일 확인 — 체험 크레딧($300, 90일)이면 **유료 계정으로 전환해야 GPU가 열린다** (전환해도 남은 크레딧은 만료일까지 유지됨이 확인된 규칙).
  2. GPU 할당량 신청 (L4 또는 T4, 스팟/선점형으로 단가 절감).
  3. 배치 생성 → 결과는 저장소(버킷)로 자동 적재 → 인스턴스 삭제. **인스턴스를 지우는 것까지가 작업 완료 조건** (켜두면 크레딧이 새는 구조).

### 3-3. 카탈로그 생산 방식 (많이 만드는 게 아니라 잘 거르는 것)
- 무드 taxonomy 고정: 카페·집중/업무·라운지·헬스장·미용·병원 대기·소매·수면 등 매장 업종 + 영상 무드(브이로그·기업·영화풍)를 사이트 기존 분류(Focus, Lounge, Cinematic 등)와 합쳐 12~15개로 확정.
- 생산 비율: 목표 등록 수의 **10배 생성 → 자동 1차 선별(음량, 무음·클리핑, 반복 구간, 길이) → 사람 귀 최종 선별 → 상위 10%만 등록.** 선별에서 떨어진 곡은 폐기가 아니라 로컬 보관 (나중에 기준이 바뀌면 재심 가능).
- 품질 게이트: 파일럿 전에 블라인드 청취 테스트 — 기존 매장 음악 서비스 곡과 섞어 20곡, "어느 쪽이 AI인지·매장에 틀 수 있는지"를 모르고 평가. 여기서 실사용 불가 판정이 과반이면 모델 조합부터 다시 잡는다.
- 곡 길이·구성: 매장용은 2~4분 + 자연스러운 반복(루프) 가능 구조 우선. 보컬곡은 매장 수요가 낮으니 카탈로그의 20% 이하로 제한.

### 3-4. 검증 게이트 고도화 (기존 4단계 + 2개 추가)
기존: ① 상업 플랜 구독 증빙 ② 구독 시작일 이후 생성 여부 ③ Sync-Only 차단 ④ 파일 지문 중복.
추가 도입:
- **⑤ 유사도 검사 (음향 지문 대조):** 남의 곡과 멜로디가 겹치는 곡을 거르는 단계. 지금 게이트는 "재료가 합법인가"만 보고 "결과물이 남의 것과 닮았는가"를 안 본다 — 실제 분쟁은 대부분 여기서 터진다. 외부 탐지 API 또는 오픈 지문 도구로 1차 거름망.
- **⑥ AI 표시·출처 자동 기록:** 인공지능기본법 제31조 표시 의무를 곡 단위로 자동 처리 (5-2 참조). 생성 출처(모델/플랜)를 곡 정보에 상시 노출하는 현행 방식은 유지 — 이게 오히려 우리 차별점이다.
- 외부 창작자 곡은 관리자 수동 검수 유지. 단, 증빙 위조에 대비해 영수증 원본 파일 보관 + 플랜 기간 대조를 절차서에 명문화.

### 3-5. 정산 시스템 교체 — "재생당 10원" 폐기
- 고정 단가 정산은 ① 매출이 없어도 빚이 쌓이고 ② 봇 재생 사기의 표적이 된다 (Deezer 실측: AI 곡 재생의 최대 85%가 사기 재생으로 수익 차단됨).
- **풀(pool) 배분으로 교체:** 매월 실제 매출의 50%를 풀로 확정 → 매장 실재생 시간(60%) + 라이선스 사용 건수(40%) 가중치로 배분. 매출 0이면 정산 0, 구조적으로 적자가 안 난다.
- 자사 카탈로그 곡의 몫은 회사 운영비로 회수 — 초기에 외부 곡이 적을 때 풀이 마르는 것을 막는 완충 장치.
- 부정 재생 방지: 같은 계정 반복 재생 제외, 매장은 사업자 인증된 플레이어에서만 집계, 라이선스는 다운로드·사용 신고 단위 집계 (기존 30초 하트비트 집계 로직을 매장 플레이어에도 이식).

### 3-6. 매장 플레이어 (신규 도입)
- 매장용은 일반 스트리밍 화면이 아니라 **틀어놓고 잊는 기계**여야 한다: 업종·시간대별 자동 선곡, 곡 사이 음량 평준화, 인터넷 끊김 시 오프라인 재생(캐시), 영업시간 스케줄.
- 사업자 인증(사업자등록번호) 단위로 계정 발급, 매장 1곳 = 라이선스 1개 원칙을 약관과 플레이어 양쪽에 구현.

### 3-7. 유통 메타데이터 체계 (유통사 기본기)
- 곡마다 **ISRC 발급**: 국제 표준 음반 코드. 한국 발급 기관은 한국음반산업협회(isrc.or.kr / 음악통합관리시스템 MIMS), 등록자 회원으로 가입하면 자체 코드로 연간 대량 발급 가능. 해외 플랫폼 유통과 정산 대조의 기준 키가 된다.

- 아티스트명(가상의 프로젝트명) 운영 규칙: 자사 카탈로그는 무드별 프로젝트명 몇 개로 묶어 발매 — 실존 인물로 오인되는 이름 금지, AI 프로젝트임을 프로필에 표기.

## 5. 법적 검토

> 읽는 법: 각 항목은 [규칙] → [우리에게 생기는 일] → [할 일] 순서. 난이도가 아니라 위험도 순으로 배열했다.

### 5-1. 🔴 "100% 검증·보장" 문구 — 표시·광고 리스크 [변호사 확인]
- [규칙] 근거 없는 단정적 광고는 「표시·광고의 공정화에 관한 법률」상 부당한 표시·광고(거짓·과장)에 해당할 수 있고, 실제 피해가 생기면 민사 책임과 함께 플랫폼이 내세운 "보장" 자체가 계약상 의무로 해석될 여지가 있다.
- [현실] 지금 검증은 "유료 플랜으로 만들었다 + 중복 아니다"까지다. 학습데이터의 적법성, 남의 곡과의 유사성까지 보장하지 못한다. Suno 곡은 저작권을 회사가 보유하고 이용권만 주는 구조이며, 순수 AI 곡은 저작권 성립 자체가 부정될 수 있어 "권리를 보장한다"는 표현은 이중으로 위험하다.
- [할 일] 대외 문구를 실체에 맞게 축소: "100% 검증·보장" → **"검증 인증 + 분쟁 발생 시 소명 자료 제공·절차 대행"**. 보장이 아니라 절차를 파는 것으로 바꾸면, 라이선스 상품의 가치(인증서·소명 대행)는 유지하면서 지킬 수 없는 약속은 사라진다. 사이트 메인·요금제·약관의 해당 문구를 전수 교체하는 것이 법적 조치 1순위다.

### 5-2. 인공지능기본법 제31조 — AI 생성물 표시 의무
- [규칙] 「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」 제31조: 생성형 AI 결과물임을 표시해야 한다. 법은 2026-01-22 시행됐고, 과태료 등 제재는 최소 1년 유예된 상태로 가이드라인이 정비 중이다.
- [우리에게 생기는 일] 곡·앨범·플레이어 화면에 AI 생성 사실과 제공자(모델)를 표시해야 한다. AVIBE는 이미 곡마다 AI 제공자를 표기하는 구조라 **오히려 준수가 차별점이 되는 드문 케이스**다.
- [할 일] 자사 카탈로그에도 같은 표기 적용, 매장 플레이어에도 "AI 생성 음악" 표기 위치 확보 (손님에게 보이는 화면·영수증·소개 페이지). 표시 방식 세부 기준은 시행령·가이드 확정 시 1회 재점검.

### 5-3. 저작권 성립 문제와 음저협(KOMCA) — 국내 정식 유통이 막힌 이유
- [규칙] 한국 정부·저작권 당국의 입장은 "인간의 창작적 기여가 없는 순수 AI 결과물은 저작물로 보호받기 어렵다"는 쪽이다. 음저협은 2025-08 AI 활용곡 등록 기준을 내놨다가 22일 만에 철회했고, 아직 정해진 기준이 없다. 멜론 등 국내 플랫폼은 음저협 등록 음원 중심이라 **순수 AI 곡의 국내 정식 유통은 현재 사실상 보류 상태**다.
- [우리에게 생기는 일] ① 자사 카탈로그를 멜론·지니에 올리는 계획은 지금 세우면 안 된다 ② 대신 이 사실이 매장 BGM의 세일즈 포인트가 된다 — 음저협 관리 저작물이 아니므로 공연권료 징수 대상에서 빠진다 (5-5) ③ 우리 사업의 자산은 "저작권"이 아니라 카탈로그 파일 + 검증 기록 + 고객 계약이라는 점을 경영 전제로 명시해야 한다.
- [할 일] 음저협 기준 제정 동향을 분기 1회 확인하는 담당만 지정. 기준이 생기면 국내 유통 진입을 그때 재평가.

### 5-5. 매장 공연권료 — "저작권료 0원"의 근거와 한계 [변호사 확인]
- [규칙] 50㎡ 이상 영업장은 음악을 틀면 공연권료(음저협 공연사용료 + 공연보상금)를 내야 하고, 소규모는 월 4,000원부터 시작한다. 매장 음악 서비스에 가입하면 이 정산을 대행·포함해 주는 구조가 일반적이다 (기존 서비스 월 2만~3만원대).
- [근거] 음저협에 등록되지 않은 순수 AI 곡은 협회의 관리 저작물이 아니어서 공연권료 징수 대상에서 빠진다는 것이 현재 업계 운용 (AI 매장음악 선행 서비스들이 같은 논리로 "저작권료 0원"을 표방 중).
- [한계] ① 우리 카탈로그에 **외부 창작자의 Suno 곡이 섞이면** 그 곡도 같은 논리가 적용되는지(곡 자체는 미등록이라도 권리 구조가 다름) 별도 확인 필요 ② "0원" 표방은 5-1과 같은 표시·광고 잣대로 보므로, 문구는 "공연권료가 발생하지 않는 AI 음원"처럼 전제를 드러내는 방식이 안전하다.
- [할 일] 매장 상품 출시 전, 이 논리 전체를 변호사 1회 검토로 확정하고 검토 의견을 문서로 보관. 이 문서가 영업 현장에서 분쟁이 생겼을 때의 방패다.

### 5-6. 외부 플랫폼 소송 동향 — 남의 곡을 받는 게이트의 리스크
- Suno·Udio는 2024년 대형 음반사 3사에 피소 → 2025년 말 UMG·Warner와 잇달아 합의(라이선스 모델로 전환), **Sony는 미합의로 소송 진행 중**, 2026-09에는 Suno v6 대상 새 소송(약 6만 곡)까지 제기됐다.
- Udio는 합의 후 다운로드가 막힌 "울타리 안 스트리밍"으로 바뀌었다 → **Udio 곡을 파일로 받아 유통하는 전제 자체가 흔들린다.** 게이트의 제공자 정책표(LicensePolicies)를 현재 시점으로 갱신하지 않으면, 받을 수 없는 곡을 받는다고 광고하는 꼴이 된다.
- [할 일] 제공자별 정책표를 분기마다 현행 약관과 대조·갱신 (게이트 관리자 기능에 이미 정책 매트릭스가 있으니 운용 절차만 만들면 됨). 합의·판결로 정책이 바뀌는 속도가 빠른 시장이라, 이 갱신을 안 하면 검증 플랫폼의 신뢰가 무너진다.

### 5-7. 신고·분쟁 대응 (OSP) — 이미 있는 권리보호센터의 법적 위치
- 권리 침해 신고를 받으면 임시조치(내리기)를 하고 게시자 소명을 받는 절차는 온라인서비스제공자의 면책 구조와 연결된다. AVIBE에 권리보호센터·분쟁(Dispute) 콘솔이 이미 구현돼 있는 것은 실제 강점이다.
- [할 일] 절차를 약관이 아니라 **운용 규정 문서**로 확정: 신고 접수 → 즉시 임시조치 → 7일 내 소명 심사 → 복원/삭제 결정 → 이력 보관. 매장·라이선스 고객에게는 "내 영상/매장이 경고를 받으면 이 절차로 소명해 준다"를 계약 서비스로 명시 (이게 5-1에서 말한 '절차를 파는 것'의 실체다).

### 5-8. 사업자 신고 — 유통사를 하려면 필요한 행정 [행정사/변호사 확인]
- **음악산업진흥에 관한 법률 제16조:** 음반·음악영상물 **제작업·배급업**, 그리고 **온라인음악서비스제공업**은 시장·군수·구청장에게 **신고**해야 하는 업종이다. AVIBE는 스트리밍(온라인음악서비스제공업)이 이미 해당하고, 자사 카탈로그 배급까지 하면 배급업도 해당한다. 무신고 영업은 제재 대상.
- 그 외 일반 요건: 사업자등록(업종 추가), 온라인 판매에 대한 통신판매업 신고, 결제(PG) 가맹 심사 시 사업자 서류.
- [할 일] 착수 체크리스트에 "제작업/배급업/온라인음악서비스제공업 신고 3종"을 넣고, 현재 운영 주체가 이미 신고했는지부터 확인. 안 돼 있으면 통합안 착수와 동시에 진행 (신고 자체는 서류 절차 수준).

### 5-9. 정산·세무
- 외부 창작자 정산은 사업소득 원천징수 3.3% 적용이 일반적이고 (사이트 대시보드에도 이미 표기돼 있음 — 유지), 정산 주기·최소 지급액을 파트너 계약서에 명시.
- 매장·라이선스 구독은 부가세 포함/별도 표기 통일, 세금계산서 발행 절차 (사업자 고객은 세금계산서를 요구한다 — B2B의 기본).
- 자사 카탈로그 매출은 전액 회사 매출로 단순하다. 풀 배분 회계는 "매출 → 풀 확정 → 배분" 3단계 장부를 월 1회 마감 문서로 남길 것.

### 5-10. 상표·도메인
- AVIBE 상표 등록 여부 확인 및 출원 (음악 스트리밍·BGM 서비스 지정상품). avibe.kr 도메인 확보 후 avibemusic.com과 통일 (1장 참조). 이름이 겹치는 해외 서비스가 있는지 출원 전 검색 1회.

## 6. 실제 AI 음원 유통사는 어떻게 돌아가는가

### 6-1. 유통사의 일 (쉬운 말로)
유통사는 곡을 "가게 진열대"에 올려주는 회사다. 하는 일은 다섯 가지: ① 곡과 정보(메타데이터)를 각 플랫폼 양식에 맞게 납품 ② 곡의 주민번호인 ISRC 관리 ③ 플랫폼에서 발생한 돈을 수금 ④ 권리자에게 정산 ⑤ 문제가 생긴 곡의 내리기(테이크다운)와 분쟁 대응. **플랫폼이 정하는 곡당 단가는 유통사가 못 바꾼다** — 유통사의 경쟁력은 수수료율, 납품 범위, 정산 투명성, 분쟁 대응에서 갈린다.

### 6-2. 돈의 흐름과 수수료 현실
- 글로벌 스트리밍: 스포티파이 등이 곡당 평균 몇 원 수준으로 지급 → 유통사가 수수료를 뗀다. 수수료 모델은 세 가지뿐이다: 연 구독료 + 수수료 0% (DistroKid 연 $24.99~), 곡당 수수료 9~15% (CD Baby 9%, RouteNote 무료 티어 15%), 곡당 정액 (AI 전문 ONCE는 AI 곡 1곡 $2).
- 즉 **남의 곡을 글로벌에 올려주는 것만으로는 큰돈이 안 된다.** 곡당 수익 자체가 작기 때문이다. 유통사 사업이 되는 경우는 둘뿐: 물량이 압도적으로 많거나(애그리게이터), **우리처럼 팔 곳(BGM·라이선스)을 직접 갖고 있을 때**다. 후자가 통합안이 서는 이유다.
- 국내 스트리밍 정산은 음저협·유통사·플랫폼이 나눠 갖는 구조지만, 5-3대로 AI 곡은 등록 기준이 없어 이 흐름 자체에 아직 못 들어간다.

### 6-3. 채널별 현실표
| 채널 | 지금 가능한가 | 조건·주의 |
|---|---|---|
| 자사 플랫폼 스트리밍 (쇼룸) | ✅ 즉시 | 공짜 전시장으로 운용 |
| 매장 BGM 납품 | ✅ 즉시 | 문지기가 없다. 사업자 계약 + 플레이어가 전부 |
| 영상 라이선스 판매 | ✅ 즉시 | 인증서 발급 체계만 만들면 됨 |
| 유튜브 (자체 채널 + Content ID) | ✅ 가능 | BGM 채널 운영, 자사 곡 Content ID 등록으로 사용 추적·수익화 |
| 글로벌 DSP (스포티파이 등) | ⚠️ 선별만 | 애그리게이터 경유. AI 정책이 갈린다 — DistroKid·LANDR·RouteNote는 AI 표기 시 수용, **TuneCore·CD Baby는 완전 AI 곡 거부**. 대량 업로드는 스팸 정책으로 계정 위험 (스포티파이는 1년간 스팸 곡 7,500만 개 삭제 발표) |
| 국내 DSP (멜론·지니 등) | 🔴 보류 | 음저협 AI 등록 기준 부재 (5-3) |

### 6-4. 그래서 AVIBE의 유통사 정의
남의 곡을 스포티파이에 대신 올려주는 회사가 아니라, **"AI 곡을 만들어(또는 검증해) → 매장과 영상 시장에 직접 파는, 판매 채널을 가진 유통사"**로 정의한다. 글로벌·국내 DSP 유통은 카탈로그와 매출이 쌓인 뒤 붙이는 확장 옵션이다. 이 순서를 뒤집어 DSP 유통부터 하면, 곡당 몇 원짜리 정산을 받으며 계정 정지 위험만 지는 구조가 된다.

## 11. 부록

### 11-1. 용어 풀이
- **공연권료** — 매장에서 음악을 틀 때 내는 돈. 작곡·작사가 몫(공연사용료)과 가수·음반제작자 몫(공연보상금)을 합친 말.
- **Sync-Only** — 영상 배경음악으로만 쓸 수 있고 곡 단독으로는 유통할 수 없는 라이선스 종류.
- **ISRC** — 곡의 국제 주민번호. 유통·정산의 기준 코드.
- **OSP** — 온라인서비스제공자. 신고가 들어오면 일단 내리고 소명을 받는 절차를 지키면 책임을 덜 받는 구조.
- **풀(pool) 배분** — 재생 횟수마다 정해진 돈을 주는 게 아니라, 번 돈 전체의 일정 비율을 한 주머니에 넣고 사용 비율대로 나눠 갖는 방식.
- **스팟(선점형) 인스턴스** — 남는 GPU를 싸게 빌리는 방식. 중간에 회수될 수 있어 일회성 배치 작업에 적합.

- 순서: 0단계에서는 베이스 모델로 카탈로그부터 만들고(모델 학습부터 하면 일정 전체가 밀린다), 선별 데이터가 1,000곡 단위로 쌓인 뒤 전용 모델 v1을 학습한다. 로드맵 1단계와 3단계 사이에 "모델 v1"을 끼우는 것으로 반영.
- 본질: 우리의 해자는 베이스 모델이 아니라 **선별 데이터 + 매장 계약 + 검증 기록**이다. 모델은 그 위에 얹는 증폭기다.

## 13. 추가 검토 (2026-11-10) — "일반 사용자도 Suno처럼 생성하게 할 것" 전제 반영

사용자 확정 전제: 생성 기능은 내부 카탈로그 생산 전용이 아니라 **일반 사용자에게도 공개**한다. 이 전제를 넣으면 판정이 이렇게 바뀐다.

### 13-1. 공개 생성, 원가만 보면 오히려 된다
- ACE-Step급 경량 모델은 곡 1개 생성에 GPU 10~30초. 스팟 단가로 곡당 약 1~4원, 비싼 정가 GPU로도 10원 안쪽이다.
- Suno의 적자는 곡당 원가 때문이 아니다 — 하루 700만 곡 규모의 대형 모델 서빙, 무료 이용자 남용, 음반사 라이선스 비용이 겹친 결과다. 우리 규모(하루 수천 곡)에서는 원가 구조가 완전히 다르다.
- 즉 공개 생성의 생사는 원가가 아니라 **놀고 있는 GPU(유휴 서버비)와 무료 남용 관리**에서 갈린다.

### 13-2. 적자 안 나는 공개 생성의 조건 5개 (전부 기본값으로 채택)
1. **서버리스/자동 꺼짐 GPU:** 요청이 있을 때만 GPU가 켜지고 없으면 0으로 줄어드는 구조. 24시간 켜두는 순간 적자 시작.
2. **무료는 맛보기만:** 하루 3~5곡, 다운로드는 유료부터. Suno도 합의 이후 무료 다운로드를 막고 유료에 월 상한을 걸었다 — 같은 이유다.
3. **유료 크레딧제:** 월 9,900원에 생성 ○○곡 + 상업 이용권 + 유통 신청 자격. 무거운 이용자 300곡을 다 써도 연산 원가는 1,000~3,000원 수준이라 마진이 남는다 (위 13-1 단가 기준).
4. **정산과 생성의 분리:** 생성한 곡이 자동으로 돈을 버는 구조 금지. 정산은 매장·라이선스 같은 실제 유료 채널에서 팔렸을 때만 — 이걸 섞으면 봇이 생성→재생을 무한 반복하는 사기 공장이 된다.
5. **포지션 고정:** "Suno보다 좋다"로 열면 품질 비교에서 진다. 우리의 문장은 **"만들면 바로 팔 수 있는 생성"** (생성 → 검증 → 매장/라이선스 유통까지 한 계정)과 **"매장 사장이 직접 만드는 우리 가게 음악"** (공연권료 없는 자기 매장 BGM 자가 생산). 이 둘은 Suno가 안 하는 일이다.

### 13-3. 12장 판정과의 관계
- 자체 대형 모델 학습 반려 판정은 **오히려 강화**된다. 공개 서비스는 서빙 비용까지 매달 나가므로, 가볍고 빠른 파인튜닝 모델이어야 원가 구조가 산다.
- 공개 시점: 카탈로그·매장 파일럿으로 "팔리는 곳"을 먼저 만들고, 생성 공개는 그 다음 단계에서 여는 순서를 유지한다. 팔 곳 없이 생성부터 열면, 만든 곡 둘 데 없는 이용자만 쌓인다 — Suno 이용자가 겪는 문제 그대로다.

## 14. 추가 검토 (2026-11-10) — 정책·약관 제약 설계 (LUNO식 플랜 제약 운용)

사용자 지적대로, 공개 생성의 통제는 기술보다 **정책·약관이 본체**다. Suno도 무료=비상업·유료=상업 가능·다운로드 상한을 전부 약관으로 운용하고, AVIBE 기존 게이트(플랜별 정책 매트릭스)가 이미 같은 방식이다. 아래 제약표를 기본값으로 채택한다.

### 14-1. 플랜별 권리·한도표 (약관 별표로 고정)
| 항목 | 무료 | 유료 (월 9,900원~) |
|---|---|---|
| 생성 한도 | 하루 3~5곡 | 월 300곡 (초과분 크레딧 구매) |
| 다운로드 | 불가 (듣기만) | 가능 |
| 상업적 이용 | **불가** (개인 감상만) | 가능 (구독 중 생성한 곡, 해지 후에도 유지) |
| 유통 신청 자격 | 없음 | 있음 (검증 게이트 통과 시) |
| 정산 참여 | 없음 | 실유료 채널 판매분만, 풀 배분 |
| AI 표시 | 전 곡 의무 (공통) | 전 곡 의무 (공통) |

### 14-2. 금지·제재 조항 (정책 문서 + 약관)
- 실존 가수 이름·목소리 모방 프롬프트 금지, 타인 가사 그대로 입력 금지 → 적발 시 곡 삭제 + 경고 누적 제재 (경고→생성 정지→계정 해지 단계표)
- 계정 공유·재판매·자동화 대량 생성(봇) 금지 → 기술 탐지와 연동
- 생성물을 "사람이 만든 곡"으로 속여 외부 유통 금지 (AI 표기 유지 의무)
- 정산 부정 (자기 곡 자기 재생 등) 적발 시 정산 취소·환수 조항

### 14-3. 약관만으로 안 되는 것 3개 (여기만 기술·법률로 보완)
1. **봇은 약관을 안 읽는다** — 한도·금지는 코드로 강제해야 한다 (생성 쿼터, 본인인증/결제수단 확인, 파일 지문 탐지). 약관은 "어기면 제재한다"는 근거일 뿐, 집행은 시스템이 한다.
2. **없는 권리는 약관으로 못 만든다** — 모델 라이선스가 비상업(MusicGen 등)이면 우리 약관에 "상업 가능"이라 써도 무효에 가깝다. 그래서 허용 모델 화이트리스트(5-4)가 약관의 전제다.
3. **법 위에 약관은 없다** — AI 표시 의무(인공지능기본법), 환불 등 소비자 보호 규정, 「약관의 규제에 관한 법률」상 불공정 조항(과도한 면책·일방 변경)은 약관으로 못 비킨다. 또 광고 문구("100% 보장")와 약관 속 면책이 서로 모순되면 약관이 아니라 광고 쪽이 문제 된다 (5-1).

## 15. 추가 확정 (2026-11-10) — AVIBE의 정체성: "열린 인증·유통 허브"

사용자 정리로 확정된 포지션: **Suno·Udio는 자기 울타리 안에 가두려 하고, AVIBE는 어디서 만들든 인증받아 팔 수 있는 열린 허브다.** 생성은 AVIBE 안에서도 가능하지만 본체는 인증+유통이다.

### 15-1. 권리 표현의 정정 (계약·인증서 문구의 기준)
- "유료 구독이면 소유권이 생성자 것"은 플랫폼마다 다르므로 그대로 쓰면 틀린다:
  - **Suno:** 유료 회원에게 **상업적 이용권**을 줄 뿐, 곡의 소유권(저작권)은 Suno가 보유한다고 약관에 명시. 무료 곡은 Suno 소유.
  - **Udio:** 유료 회원에게 상업적 이용권 부여 (역시 이용권 구조).
  - **AIVA Pro:** 생성자가 저작권을 갖는다고 명시 — 여기가 예외적으로 "소유권"이 맞다.
  - 공통 한계: 순수 AI 생성물은 저작권 성립 자체가 국가별로 불확실 (5-3).
- 따라서 AVIBE 인증서·계약서의 공식 표현은 **"상업적 이용권 보유 인증"**으로 통일한다. 인증이 증명하는 것: ① 생성 시점에 해당 플랫폼 유료 상업 플랜을 보유했음 ② 그 플랫폼의 당시 정책상 상업 이용이 허용되는 곡임 ③ 중복·재등록이 아님. 인증 시점의 제공자 정책 스냅샷을 함께 보관해, 나중에 정책이 바뀌어도 "그 당시에는 적법했다"를 증명할 수 있게 한다.
- 유통 계약에는 생성자의 권리 보증 + 분쟁 시 1차 책임(면책) 조항을 둔다 — 우리가 파는 것은 "권리의 진실 보장"이 아니라 "확인 절차를 거쳤다는 인증과 유통"이기 때문이다 (5-1 문구 축소와 같은 선).

### 15-2. 울타리 전략이 만드는 빈자리와 우리의 보험
- Udio는 합의 후 다운로드 자체를 막았고, Suno도 다운로드 상한·유료화를 강화하는 중 — 울타리가 높아질수록 "만들었는데 밖에 못 파는" 창작자가 쌓인다. 이 불만이 열린 허브의 수요다.
- 역으로 리스크도 같다: 울타리가 더 높아지면 외부 곡 유입이 줄 수 있다. **AVIBE 자체 생성이 그 보험이다** — 밖에서 못 가져오면 안에서 만들면 되고, 허브는 어느 쪽 공급으로도 돈다. 생성과 유통을 둘 다 가진 구조가 이 전제에서 완성된다.
