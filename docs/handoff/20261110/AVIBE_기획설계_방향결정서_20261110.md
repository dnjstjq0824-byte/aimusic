# AVIBE 기획·설계·정책 방향결정서 (2026-11-10)

역할 합의: **기획·설계·정책 방향 결정과 검증·판정은 Muse**가 맡고, 집행은 Spark 1.3(엔진)이 하고, 껍데기(화면) 작업은 담당이 지정될 때까지 보류한다. CEO 확인은 8장에 적은 4개 지점뿐이고, 나머지는 이 결정서대로 진행하고 결과로 보고한다.
근거 문서: 종합검토 보고서 / 작업지시서 / 약관 초안 / 엔진 수용 체크리스트 (전달 패키지 동봉).

## 1. 제품 정체성 (확정)
- 한 줄: **"어디서 만들든, 인증받아 팔 수 있는 열린 AI 음악 허브. 안에서 만들 수도 있다."**
- 본체는 인증+유통, 생성은 내장 기능이자 외부 공급이 막힐 때의 보험이다.
- 하지 않는 것: Suno와의 품질 정면승부 / 일반 청취자 스트리밍 유료화 전면전 / 글로벌 DSP 무차별 대량 업로드 / "100% 보장"식 단정 광고.

## 3. 서비스 설계 방향
- **유지·정상화:** 음원 탐색, 플레이리스트, 권리보호센터, 파트너 스튜디오, 관리자 콘솔 (이미 있는 골격 — 새로 만들지 않는다)
- **신설:** ① 생성 (ACE-Step 1차, 공개는 Phase 3) ② 매장 BGM 구독 + 매장 플레이어 ③ 영상 라이선스 구독·마켓
- **정비:** 홈페이지 통계·문구 표기 (6장 결정), 약관 4종 본문 게시 가능 상태로, 푸터 사업자 정보

## 5. 정책 방향 결정 (기획자 결정 — CEO 이의 없으면 이대로 집행)
1. **정산 방식:** 초기 정본은 **유통 순매출 70:30 (파트너 70)** 으로 약관에 고정한다. 단 정산 원천은 실유료 채널(매장·라이선스·생성 구독 연동 판매)뿐으로 한정한다 — 재생만으로 돈이 생기는 구조는 두지 않는다. **배분 기준 (2026-11-10 추가 확정):** 직접 판매·라이선스 건은 해당 음원에 직접 귀속하고, 매장 구독료 풀은 30초 이상 재생된 매장 재생 시간 비례로 나눈다 — 30초 집계는 이 풀 배분에만 쓴다. 가중 풀 배분은 초기 규모에 비해 운영이 무거우므로, 채널 매출이 실제로 붙은 뒤 데이터로 재판정하는 2단계 과제로 미룬다. 이유: 지금의 법적 리스크는 방식의 좋고 나쁨이 아니라 **공개 표기(70:30)와 약관의 불일치**라, 표기와 약관부터 일치시키는 게 우선이다.
2. **"100%" 광고 문구:** 축소한다. "100% 검증/상업 이용 가능" → "4단계 인증을 통과한 음원만 유통" 같은 사실 표현으로 교체한다. 약관으로 한정 해석을 거는 것만으로는 표시광고 리스크가 안 없어진다. 화면 작업지시서(작업지시_AVIBE_껍데기_화면)로 분리했다 — 문구 교체 자체는 소스에 이미 반영된 상태(라이브 미배포)라, WI-01 배포로 해소되는 것이 우선이다.
3. **인증 문구:** "상업적 이용권 보유 인증"으로 전 표면 통일 (약관 초안 제12조가 정본).
4. **플랜·환불:** 약관 초안의 플랜표(무료 일 3~5곡·유료 월 300곡)와 "7일 이내 미사용 전액 환불"(현행 표기 승계)을 정본으로 한다.
5. **생성 공개 순서:** 카탈로그와 매장 파일럿으로 "팔리는 곳"을 먼저 만들고 생성은 그 다음에 연다 (보고서 13장).
6. **GPU와 크레딧의 분리 (2026-11-10 기획자 결정):** 구글 체험 크레딧은 체험 상태 그대로는 GPU를 못 쓰는 게 맞다 (유료 전환 시 열리지만, 그 선택을 강요하지 않는다). 크레딧은 API 서버·스토리지 같은 **비GPU 인프라**에 쓰고, GPU 생성은 **쓴 만큼만 내는 서버리스 종량제**로 분리한다. 유휴 과금 0 구조(5장 정산·13장 조건)와도 일치하고, 크레딧 확인이 전체 일정을 막지 않게 된다. 카탈로그 일괄 생산이 필요해지면 그때 전환 여부를 다시 판단한다.

## 6. 디자인 설계 방향
- 기존 껍데기의 디자인 언어를 유지하고, 신설 표면(생성·매장·라이선스)은 같은 언어로 확장한다 — 전면 리디자인을 새로 벌이지 않는다.
- 기준은 전 제품 공통 표준 그대로: 단색 플랫·흰 배경·실제 데이터 밀도, 그라데이션·장식·AI티 금지, 언어·통화·국가를 분리한 글로벌 설계.
- 신설 표면은 시안이 나오면 기획자가 먼저 직접 눌러보고 결함을 고친 뒤에 보고한다.

## 7. 단계 계획
| 단계 | 내용 | 완료 판정 |
|---|---|---|
| Phase 0 정상화 | 서버·결제·로그인 복구, 약관 게시, 사업자 정보, 문구 정비 | 라이브에서 전 페이지·약관·로그인 정상 실측 |
| Phase 1 유통 실가동 | 인증 게이트 실운영, 외부곡 유입, 카탈로그 축적 (크레딧 생성 포함) | 인증 곡 수·등록 전환율 실측 |
| Phase 2 매장 파일럿 | BGM 구독 + 매장 플레이어, 매장 50곳 목표 | 유료 매장 수·유지율로 생사 판정 |
| Phase 3 생성 공개 | 일반 공개, 크레딧제 | 생성 원가율·유료 전환율 실측 |
| Phase 4 확장 | 라이선스 마켓 본격화, LoRA 전용 모델 검토 (선별 1,000곡 축적 후) | 데이터로 재판정 |

## 8. CEO 확인이 필요한 것 — 우선순위 재배열 (2026-11-10 CEO 지시 반영)
1. **(최우선) 각 Phase의 운영 배포 승인** — 플랫폼을 만드는 것이 본선이고, 배포는 단계마다 CEO 승인을 받는다.
2. **(공개 유료화 직전 마감) 음악산업진흥법 신고 3종** — 만드는 동안은 불필요. 돈을 받기 시작하는 공개 시점 전이 마감선이다.
3. **(공개 유료화 직전 마감) 약관 변호사 검토** — 초안은 이미 작성돼 있고 내부 기준으로는 충분. 법률 검토는 공개 직전에 한 번에 한다.
4. **(확인 목록에서 제외) 구글 크레딧 종류·만료일** — 아래 5-6 결정으로 GPU를 크레딧에 묶지 않기로 했으므로, 더 이상 CEO 확인이 필요 없다.

## 9. 금지선
- 운영 배포·결제·신고 등 되돌릴 수 없는 일은 8장의 확인 없이 하지 않는다.
- 완료 주장은 라이브 실측 증거가 있을 때만 한다. 못 한 것은 BLOCKED·NOT TESTED로 남긴다.
- 집행 세션(Spark)이 방향을 임의로 바꾸지 않는다. 방향 변경이 필요하면 이 결정서를 고치는 것으로만 한다.
