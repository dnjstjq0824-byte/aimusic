## 프롬프트 본문 (여기서부터 복사)

너는 AVIBE(avibemusic.com)의 내부 엔진 구현 담당이다. 이번 지시는 **검토 전용**이다. 코드를 한 줄도 바꾸지 말고, 배포도 하지 마라. 읽고, 대조하고, 보고하는 것까지가 이번 범위다.

### 배경 (기획 측 확정 사항 — 전제로 받아들일 것)
- AVIBE의 정체성은 "열린 인증·유통 허브 + 내장 생성"이다. 어디서 만들든 유료 상업 플랜 인증을 받으면 유통하고, 자체 생성도 제공한다. 화면 작업은 현재 담당이 없어 보류 중이며 너의 범위 밖, 엔진은 너의 소관, 방향 결정과 최종 검증은 기획(QA) 측이 한다.
- 라이브 실측 상태(2026-11-10, 기획 측 확인): API가 임시 터널 경유로 죽어 있음(530), 약관 페이지 4종이 전부 서버 오류, 파트너 로그인도 서버 오류로 실패, 토스 결제 키 미설정, 푸터에 사업자 표시사항 없음, 홈페이지에 "100% 검증" 문구와 "정산 70:30" 표기가 있음.
- 확정된 정책 결정: 정산은 초기 정본 **순매출 70:30(파트너 70)** 으로 약관에 고정하되 정산 원천은 실유료 채널로 한정 / GPU는 구글 크레딧에 묶지 않고 **서버리스 종량제**로 분리 / "100%" 문구는 축소 예정(껍데기 소관이라 너는 손대지 마라) / 음악산업법 신고와 약관 법률 검토는 공개 유료화 직전 마감이라 지금은 범위 밖.

### 검토 과제
- **R-1 현황 실측 (작업지시 WI-00 그대로):** 현재 저장소·배포 상태를 보고하라. 실제 API 구동 방식(임시 터널 포함), 환경변수 목록(값은 적지 마라), 결제 키 설정 여부, 배포 파이프라인, 현재 브랜치·HEAD 커밋. 기획 측 실측과 다른 점이 있으면 그 차이부터 적어라.
- **R-2 방향 충돌 점검:** 방향결정서와 보고서의 결정 사항 중 현재 코드 구조와 충돌하는 지점을 전부 찾아라. 항목마다 "어느 파일·구조와, 왜 충돌하는지, 해소 방법의 선택지"를 적어라.
- **R-3 작업량 재산정:** WI-01~WI-08의 항목별 예상 파일 수(합계 50, 상한 50)가 실제 코드 기준으로 맞는지 검증하라. 다르면 항목별로 네 재산정 값과 근거(대상 파일 목록)를 제시하라. 50을 넘으면 어느 항목을 후속 지시로 분리할지 제안하라.
- **R-4 약관 구현 항목 추출:** 약관 초안의 조항 중 시스템 구현이 필요한 것을 전부 뽑아 구현 항목으로 정리하라. 예: 플랜별 서버 권한(무료의 다운로드·유통 신청 차단), 인증 시 정책 스냅샷 저장, 제재 단계(경고→제한→해지), 정산 보류·이의신청 상태, AI 표기 메타데이터. 조항 번호와 구현 항목을 1:1로 대응시켜라.
- **R-5 생성 인프라 검토:** GPU 서버리스 종량제 분리 결정에 대해, ACE-Step 서빙 방식 후보 2~3개와 후보별 곡당 원가·콜드스타트·운영 난이도를 비교하라. 구글 크레딧은 GPU에 쓰지 않는 전제다.
- **R-6 정산 교체 범위:** 현행 정산 코드(재생당 고정액으로 알려진 구조가 실제로 무엇인지 코드로 확인)와 70:30 고정안의 차이를 적고, 기존 데이터가 있을 경우의 마이그레이션 범위와 롤백 경로를 제시하라.

### 보고 형식
- 과제별로: **판정(가능 / 조건부 가능 / 불가)** + 근거(파일 경로·코드 위치) + 남은 질문.
- 질문은 "기획 측 결정이 꼭 필요한 것"만 모아서 마지막에 한 번에 제시하라. 네가 코드에서 확인할 수 있는 것을 질문으로 돌리지 마라.
- 확인하지 못한 것은 추측으로 채우지 말고 **NOT CONFIRMED**로 표기하라.
- 보고는 착수 승인이 아니다. 이 보고를 기획 측이 검토한 뒤 별도로 착수 지시가 나간다.

### 금지
- 코드 변경, 커밋, 배포, 운영 데이터 조회·변경 일절 금지 (읽기 전용 검토).
- 껍데기(화면·디자인) 파일은 열람만 하고 수정안도 내지 마라.
- 방향 결정에 이의가 있으면 임의로 바꾸지 말고 R-2 보고에 사유와 함께 적어라.
