# 작업지시서 — AVIBE 내부 엔진 (2026-11-10)

| 항목 | 내용 |
|---|---|
| 대상 | avibemusic.com 내부 엔진 (백엔드·인증·생성·정산) |
| 수신 | Muse Spark 1.3 (엔진 구현 세션) |
| 발행 | Muse (기획·검증) — 근거 정본: 함께 전달되는 종합검토 보고서 |
| 범위 밖 | 껍데기(화면·디자인)는 이 지시의 범위 밖 — 화면 담당은 별도 지정 전까지 보류이며, 엔진은 화면 구조를 변경하지 않는다 |
| 상태 | **이 지시서 전달 ≠ 착수 승인.** PO가 착수를 명시한 뒤에 시작한다 |

## 1. 확정 방향 (이 지시서의 전제 — 임의로 바꾸지 않는다)

1. AVIBE는 **열린 인증·유통 허브**다. 어디서 만들든(타 플랫폼 생성곡 포함) 유료 상업 플랜 인증을 받으면 유통한다. 자체 생성도 내장한다.
2. 매출의 문은 **매장 BGM 구독 + 영상 라이선스 구독**이고, 일반 스트리밍은 무료 쇼룸이다.
3. 정산은 재생당 고정액이 아니라 **매출 풀 배분**이며, 정산 원천은 실제 유료 채널 판매분만이다.
4. 권리 표현의 정본은 **"상업적 이용권 보유 인증"**이다. "100% 보장"·"소유권 보장" 문구는 전 표면에서 제거한다.
5. 세부 결정은 종합검토 보고서 10장의 CEO 결정표 기본값을 따른다. 기본값과 다르게 구현해야 할 사유가 생기면 구현 전에 보고한다.

## 2. 작업 항목

### WI-00. 현황 실측 보고 (변경 0개 — 코드 수정 금지)
착수 전 현재 저장소·배포 상태를 보고한다: 실제 API 구동 방식(임시 터널 포함), 환경변수 목록(값 제외), 결제 키 설정 여부, 배포 파이프라인, 현재 브랜치·HEAD 커밋. 이 보고가 없으면 WI-01 이후를 시작하지 않는다.
- 산출: 현황 보고 1건 (아래 §6 형식)

### WI-01. 서버 정상화 (예상 6개)
- API를 임시 터널(trycloudflare) 의존에서 정식 배포로 전환한다. 터널 주소가 코드·설정에 남지 않게 한다.
- 환경변수(결제 키·DB·스토리지)를 코드에서 분리하고, 비밀값은 저장소에 커밋하지 않는다.
- 헬스체크 엔드포인트를 두고, 재배포 후 라이브에서 음원 목록·요금제가 실제로 불러와지는 상태까지가 완료다.
- 사업자 표시는 코드만 완성하고 숨김 처리한다 (사업자 미신고 상태 — 회신 문서 §6 추가 지시 참조). 값이 비면 블록이 렌더링되지 않게 하고, 신고 후 값 입력만으로 표시되게 한다.

### WI-02. 결제 연결 (예상 4개)
- 토스 결제 키를 환경변수로 연결하고, 테스트 결제로 구독 결제→플랜 승급→영수증 기록 전 과정을 동작시킨다.
- 결제 실패·취소·환불 경로가 플랜 상태를 올바르게 되돌리는지까지 포함한다.

### WI-03. 도메인·표기 통일 (예상 4개 — 엔진 몫만, 2026-11-10 정정)
- 엔진 소관(메일 발송 도메인·설정값)의 표기를 avibemusic.com으로 통일한다 (avibe.kr 잔재 제거).
- canonical·OG 등 화면 파일(web/index.html)의 표기 교체는 이 지시의 범위에서 제외한다 — 화면 담당이 지정되면 별도 지시로 분리한다.

### WI-04. 인증 게이트 강화 (예상 8개)
- 외부 플랫폼 곡 등록의 4단계(유료 플랜 증빙 → 생성일 윈도우 대조 → Sync-Only 차단 → SHA-256 중복 검사)가 우회 불가하게 서버에서 강제되는지 점검·보강한다.
- 인증 레코드에 **제공자 정책 스냅샷**(플랫폼·정책 버전·인증 일시)을 저장한다.
- 인증서·화면·문서의 권리 문구를 "상업적 이용권 보유 인증"으로 교체하고 "100% 보장" 류 문구를 전수 제거한다 (grep 결과 첨부).
- 허용 모델 화이트리스트를 코드 상수로 두고, 비상업 라이선스 모델(MusicGen 등)은 인증 단계에서 차단한다.

### WI-05. 생성 엔진 연결 (예상 18~22개 — **후속 지시로 분리**, 2026-11-10 정정)
- 1차 연결 모델은 ACE-Step (상업 가능 라이선스 근거를 코드 주석·문서에 남긴다). HeartMuLa는 2차로 분리한다.
- 운영 GPU는 **서버리스 종량제(Modal)로 확정**한다. 기존 홈 PC 생성 서버는 개발·카탈로그 배치 전용으로 한정하고, POST /generate 계약은 그대로 재사용한다.
- 모델 화이트리스트·플랜 한도·금지 프롬프트 필터·AI 표기 메타데이터가 이 항목의 완료 조건에 포함된다 (검토 보고 R-2 #10).
- 무료/유료 한도(무료 하루 3~5곡·다운로드 불가 / 유료 월 300곡)는 **서버에서 강제**한다. 화면 차단만으로는 완료가 아니다.
- 생성 결과에 AI 표기 메타데이터를 자동 부착한다.

### WI-06. 플랜·약관 권한 일치 (예상 7개)
- 플랜별 권리표(보고서 14-1)를 실제 서버 권한과 일치시킨다: 무료 계정의 상업 유통 신청·다운로드·정산 참여가 서버에서 거부되는 것까지 확인한다.
- 금지 프롬프트 필터(실존 가수명·목소리 모방 유도)와 제재 단계(경고→생성 정지→계정 해지)를 구현한다.
- 약관·정책 문안 작성까지가 이 항목의 범위다. **게시는 법률 확인(G-3) 전까지 보류**한다.

### WI-07. 정산 엔진 교체 (예상 8~10개 — **후속 지시로 분리**, 2026-11-10 정정)
- 재생 1회 10원 고정 정산을 폐기하고 **순매출 70:30 (파트너 70)** 으로 교체한다. 정산 정본은 방향결정서 5-1이다 (종전 "풀 배분" 표기는 폐기).
- 배분 기준: 직접 판매·라이선스 건은 해당 음원에 직접 귀속한다. 매장 구독료 풀은 30초 이상 재생된 매장 재생 시간 비례로 나눈다. 일반 스트리밍 재생은 정산 원천이 아니다.
- 전액 몰수(FORFEITED) 처리를 폐기하고, 해당 기간·해당 곡 한정의 **보류(HELD) + 사유 통지 + 14일 이의신청**으로 교체한다 (약관 제15조④).
- 마이그레이션은 컬럼·테이블 추가만으로 하고, 계산 방식은 설정 플래그로 전환한다. 적용 전 백업과 롤백 경로를 보고에 포함한다 (검토 보고 R-6안 수용).

### WI-08. 유통 실무 연결 (예상 4개)
- ISRC 발급 절차를 등록 플로우에 연결한다(자동 발급 또는 대행 접수 상태 관리).
- 글로벌 DSP 송출은 선별곡만 가능한 구조로 제한한다 (대량 일괄 송출 기능 금지).
- 전 곡 AI 표기(파일 메타데이터 + 플랫폼 고지) 자동화를 마감한다.

**집행 구조 (2026-11-10 검토 판정으로 개정):** 집행 측 재산정(합계 약 74~87개)을 수용해 둘로 나눈다. **1차 지시 = WI-01·02·03·04·06 (약 41~46개, 상한 50)** / **후속 지시 = WI-05·07·08.** gofmt 정리 62개 파일은 내용 변경이 없는 별도 커밋으로 상한에서 제외한다. **전제 조건: 미커밋 178개의 기준선 커밋이 먼저다** — 기준선이 없으면 변경 매핑표를 만들 수 없다. 1차 지시 착수는 기준선 커밋 완료 보고 후 PO 승인으로 한다. (WI-00은 변경 0)

## 3. 변경 범위 가드레일 (전 항목 공통, 위반 시 반려)

1. 항목별 예상 파일 수를 넘길 것 같으면 **커밋 전에 멈추고** 변경 목록부터 보고한다.
2. 전체 변경 파일 상한은 **50개**다. 초과가 불가피하면 작업을 나눠 후속 지시로 분리 제안한다.
3. 지시서에 없는 파일을 수정했으면 **별도 커밋으로 분리하고 사유를 적는다.** 무언의 동반 수정은 반려 사유다.
4. 빌드 산출물·생성 파일은 커밋하지 않는다. `.gitignore` 점검을 WI-01에 포함한다.
5. 완료 보고에 `git diff --stat` 기준 **전체 변경 파일 목록 + 파일별 대응 항목 번호(WI-xx)** 매핑표를 첨부한다. 매핑이 안 되는 파일은 미해결로 표기한다.
6. 신규 생성 파일과 삭제 파일은 수정과 구분해 별도로 센다.

## 4. 게이트 (멈춰야 하는 지점)

- **G-1: 폐지 (2026-11-10).** GPU-크레딧 분리 결정으로 크레딧 확인은 더 이상 게이트가 아니다.
- **G-2 (운영 배포):** 각 항목의 운영 반영은 PO 별도 승인 후에만 한다. 스테이징·로컬 완료를 운영 완료로 보고하지 않는다.
- **G-3 (약관 게시):** 약관·정책 문안의 실제 게시는 법률 확인 후 PO 승인을 받는다.
