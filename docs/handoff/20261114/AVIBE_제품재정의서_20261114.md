## 1. 우리가 이기는 방법

### 1.1 한 문장 정의
> **AVIBE는 AI 음악을 "들을 수 있는 것"에서 "쓸 수 있는 것"으로 바꾸는 플랫폼이다.**
> 만들고(Create) → 권리를 확인하고(Verify) → 유통하고(Distribute) → 라이선스하고(License) → 정산한다(Earn).

### 1.2 왜 Suno를 넘을 수 있는가 (내부 전략 — 외부 문구에 경쟁사 비교 금지)
- Suno는 **생성 도구**다. 결과물의 상업 이용 가능 여부는 요금제·다운로드 시점·약관 개정에 따라 달라지고, 사용자가 스스로 증명해야 한다. Udio는 2025-11-12 약관 개정 이후 전 플랜 비상업이 됐다. 즉 **생성 시장은 커지는데 "써도 되는 음악"은 부족하다.**
- AVIBE는 그 빈자리를 차지한다. 어느 엔진으로 만들었든(자체 ACE-Step 생성 + Suno Pro/Premier·AIVA Pro·ElevenLabs Creator+·Stable Audio 유료 반입) **상업적 이용권 보유 인증**을 거친 곡만 올라오고, 그 곡은 바로 매장 BGM과 영상 라이선스로 팔린다.
- 생성 품질 경쟁은 모델 회사들이 한다. 우리는 **신뢰(인증) + 수요(매장·영상 구매자) + 정산**의 3면 네트워크를 가진다. 이 네트워크는 모델이 바뀌어도 남는다.

### 1.4 북극성 지표
**월간 인증 상업 재생 분(Verified Commercial Minutes)** = 승인 매장 인증 플레이어의 집계 재생 분 + 영상 라이선스 발급 곡의 길이 합.
보조: 인증 완료 곡 수, 인증서 조회 수, 리스너 30초 이상 재생 수, 크리에이터 월 정산 대상자 수, **도입 문의 수·전환율**, 언어별 유입·가입 수, 검색 유입(콘솔 노출·클릭).

**측정 이벤트(제품 분석, 개인 식별정보 없이):** `signup_started`·`signup_completed`(유형·언어), `login_succeeded`(수단), `play_started`·`play_30s`, `playlist_created`, `track_liked`, `inquiry_opened`·`inquiry_submitted`(용도), `checkout_started`·`checkout_completed`, `locale_changed`, `share_clicked`(채널), `embed_loaded`, `create_waitlist_joined`. 수집 엔드포인트는 엔진에 두고 쿠키 없는 방식으로 한다(WI-S5).

### 1.5 문구 원칙 (전 언어 공통, 위반 시 반려)
1. 권리 표현은 **"상업적 이용권 보유 인증"**(EN: Verified commercial-use rights)만 쓴다. "100% 보장", "법적으로 안전", "저작권 보장" 금지.
2. 외부 화면·마케팅에 경쟁사 이름을 우월 비교·"대체" 대상으로 쓰지 않는다. 생성 출처 표기("플랫폼: Suno")와 가이드 페이지의 사실 설명(약관 확인 날짜 포함)만 허용한다.
3. 소비자 화면에서 엔지니어링 용어 금지: `FFprobe`, `AES-256-GCM`, `SHA-256`, `HLS`, `Gate 1→4`, `OSP 제103조` 같은 표기는 `/trust`(인증 방식) 페이지와 법적 고지 영역으로만 옮긴다.
4. 법령 근거 표기(인공지능기본법 제31조 등)는 트랙 상세의 "AI 생성 표시" 블록과 법적 고지에만 둔다.

- 현재 `users.role` = `ADMIN | PARTNER | USER`이고, **매장 사업자가 크리에이터 콘솔(PARTNER)을 같이 쓴다.** 성격이 다른 두 고객을 한 콘솔에 섞은 것이 가장 큰 구조 결함이다.

## 3. 화면 원칙 (UX)

1. **첫 화면에서 3초 안에 가치가 보인다.** 첫 방문 모달(OnboardingModal) 폐지. 신뢰 정보는 히어로 아래 한 줄 "인증 스트립"으로 대체한다.
2. **게스트 홈과 로그인 홈은 다르다.** 게스트: 가치 제안 + 바로 듣기 + 세 고객 진입. 로그인: 이어 듣기·내 플레이리스트·추천.
3. **카드의 1차 행동은 하나.** 트랙 카드 = 재생. 큐 추가·플레이리스트·신고는 더보기(⋯) 메뉴로 옮긴다. 신고를 1차 노출하지 않는다(트랙 상세 하단에는 유지).
4. **인증 상태는 브랜드 자산이다.** 인증서가 발급된 곡에만 **Verified Seal**(§4.6)을 붙이고, 누르면 인증서로 간다. 발급 전 곡에는 Seal 대신 "확인 절차 완료·인증서 발급 전" 중립 배지.
5. **원시 값 노출 금지.** `STABLE_AUDIO` 같은 enum, UUID, 내부 상태 코드를 화면에 그대로 쓰지 않는다(표시명 매핑, UUID는 "복사" 버튼 뒤로).
6. **빈 상태는 다음 행동을 준다.** 모든 빈 목록에 1개의 CTA.
7. **오류는 사람 말로, 코드는 작게.** 서버 `error.code` → 번역 키 매핑, 원문 메시지 직접 노출 금지.
8. **모바일 우선 터치.** 모바일 1차 행동 44×44px 이상, 그 외 모든 대상 24×24px 이상(WCAG 2.2 2.5.8).
9. **플레이어는 듣는 곳에만.** 인증·스튜디오·비즈니스·관리자 화면에서 숨기고, 표시되는 화면은 본문 하단 여백을 플레이어 높이만큼 확보한다(현재 푸터가 가려짐).
10. **모든 화면은 5개 언어에서 깨지지 않는다.** 고정 폭 버튼 금지, 텍스트 확장 40% 가정.

## 5. 다국어(i18n) 사양

### 5.1 지원 언어
| 코드 | 언어 | 역할 |
|---|---|---|
| `ko` | 한국어 | **원문(source)**. 모든 키는 ko에서 먼저 만든다 |
| `en` | English | 1차 번역 · **기본 폴백** |
| `ja` | 日本語 | 번역 |
| `zh-CN` | 简体中文 | 번역 |
| `th` | ไทย | 번역 |

- **공개 페이지는 URL이 언어를 정한다**(`/en/…`이면 영어). 아래 감지 순서는 ⓐ 접두 없는 로그인 후 화면·콘솔의 표시 언어와 ⓑ 공개 페이지의 "다른 언어로 보기" 제안 배너에만 쓴다.
- 감지 순서: ① 로그인 사용자의 `users.locale` ② 저장값(`avibe.locale`, try/catch) ③ `navigator.languages` 매칭(`zh-Hans*`/`zh-CN`/`zh-SG`→zh-CN, `zh-TW`/`zh-HK`/`zh-Hant*`→**en**) ④ `en`.
- 공개 페이지에서 언어를 바꾸면 같은 페이지의 해당 언어 URL로 이동하고, 로그인 상태면 `users.locale`도 저장한다.
- 언어 변경 즉시 `<html lang>`, 문서 제목, 날짜·숫자 형식이 바뀐다. 로그인 상태면 서버에 저장.
- 관리자 콘솔은 `ko`·`en` 2개만(내부 운영). 나머지 모든 사용자 화면은 5개 언어.

### 5.2 구조 (웹)
- `@nuxtjs/i18n`(내부 vue-i18n, Composition API), 전략 `prefix_except_default`(ko 접두 없음, `/en`·`/ja`·`/zh-cn`·`/th`), 네임스페이스별 JSON 지연 로딩:
  `web/i18n/locales/{ko,en,ja,zh-CN,th}/{common,auth,home,explore,track,player,library,playlist,pricing,checkout,account,legal,studio,business,generate,admin,errors}.json`
- 공개 페이지에서 감지 결과로 **강제 리다이렉트하지 않는다**(SEO). 다른 언어 제안 배너만 1회.
- 키 규칙: `네임스페이스.화면.요소[.상태]` 예) `auth.login.submit`, `errors.AUTH_INVALID_CREDENTIALS`. 문장 조립 금지 — 변수는 `{count}` 보간, 복수형은 ICU 형식.
- 날짜·숫자·통화: `Intl` 기반 `datetimeFormats`/`numberFormats`. 통화는 결제 통화(현재 KRW)를 사용자 로케일 형식으로 표기(₩5,900 / ￦5,900 / 5,900 KRW 등 Intl 결과 그대로).
- 태국어 날짜: 일반 UI는 Intl 기본(불기 연도), **인증서·약관·결제 영수증은 서력 + ISO 날짜** 병기.
- 문자열 하드코딩 차단: `scripts/check-i18n.mjs` — 웹 소스(Nuxt 이전 후 `web/app`, 이전 전 `web/src`)에서 locales·테스트 제외 한글 0건, 5개 언어 키 동치, 미사용 키 보고. CI 필수.
- 표시용 데이터도 번역 대상이다: 무드·장르·용도 태그(키는 영문 고정, 표시명은 번역), 플랫폼 표시명(고유명사 — 번역 안 함), 요금제 이름(`plan.code`), 오류 코드, 메일, 매장 플레이어 화면.
- 의사 로케일 `en-XA`(40% 확장 + 악센트)를 개발 모드에만 둬서 잘림·고정 폭을 잡는다.

### 5.3 엔진(백엔드)
- `users.locale` 컬럼 추가(기본 `ko`, 허용값 5개). `PATCH /auth/me/locale`.
- API 오류는 **안정적인 `code`가 정본**, `message`는 개발용. 웹·모바일은 code로 번역한다. 백엔드 Go 코드의 한글 문자열 65곳 중 사용자에게 보이는 것은 code로 바꾼다.
- 메일(비밀번호 재설정·이메일 인증)은 수신자 `locale` 템플릿 5종.
- 요금제 이름: `billing_plans.name_ko` 의존을 끊고 클라이언트가 `plan.code`로 번역(`pricing.plans.LISTENER_PLUS_MONTHLY.name`).
- 약관: **한국어 원문이 구속력 있는 정본.** 번역본은 법률 확인(G-3) 후에만 게시하고, 게시 시 "참고용 번역이며 한국어 원문이 우선합니다" 고지. 번역 게시 전에는 한국어 원문 + 사용자 언어로 "번역 준비 중" 안내.

### 5.4 모바일
- Flutter `flutter_localizations` + `gen-l10n`, `lib/l10n/app_{ko,en,ja,zh,th}.arb`. `app_zh.arb`에는 **간체**를 넣고, `localeResolutionCallback`에서 번체(`zh_Hant`·`zh_TW`·`zh_HK`)는 en으로 보낸다(웹과 동일 규칙). 한글 하드코딩 572곳 전부 ARB로.
- 웹과 같은 용어집·같은 키 의미를 쓴다(키 이름은 Dart 규칙의 lowerCamelCase로 변환).

## 6. 핵심 화면 정의 (요지 — 세부는 작업지시서)

### 6.1 홈(게스트)
1. 히어로: H1 KO "바로 써도 되는 AI 음악" / EN "AI music you can actually use." 서브: "모든 곡은 상업적 이용권 보유 인증을 거쳐 공개됩니다. 무료로 듣고, 매장과 영상에는 라이선스로 쓰세요." CTA 2개: [지금 듣기] [비즈니스 라이선스 보기].
2. 인증 스트립: Seal + "공개 전 이용권 확인 · 곡별 인증서 · AI 생성 표시" + [어떻게 확인하나요? → /trust].
3. 바로 듣기 레일(커버 + 제목 + 재생) → 무드/장르 칩 → 인기 차트(번호 리스트).
4. 세 고객 진입 카드: 리스너 / 크리에이터(→ /for-creators) / 비즈니스(→ /business).
5. 푸터: 기술 표기(`암호화: AES-256-GCM` 등) 삭제, 언어 선택 추가.
- 현재 H1 "나만의 스튜디오"는 게스트에게 의미가 없고, 정체성(듣기/쓰기)과 다르므로 폐기.

### 6.2 탐색
검색창 + 필터(무드·장르·BPM·길이·생성 플랫폼 표시명·인증 여부) + 정렬. 플랫폼 필터는 사실 표기용이며 기본 숨김(“더 보기”).

### 6.3 트랙 상세
상단: 커버·제목·크리에이터·Seal·[재생] [플레이리스트] [⋯]. 우측(데스크톱)/하단(모바일): **라이선스 패널** — "이 곡을 매장/영상에 쓰기" CTA(→ 비즈니스), 인증서 상태. 그 아래 AI 생성 표시, 파형, 비슷한 곡. 신고는 맨 아래 텍스트 링크. 트랙 UUID는 "ID 복사" 버튼으로만.

### 6.4 요금제
탭 3개: 리스너 / 크리에이터 / 비즈니스. 리스너 탭은 현행 요금(Free, 리스너 플러스 ₩5,900, 스튜디오 프로 ₩12,900 — 스튜디오 프로는 크리에이터 탭으로 이동). **비즈니스 요금은 "도입 문의"로 운영한다(2026-11-14 CEO 확정)** — 가격 표시 없음, 가격 임의 창작 금지. 환불 정책 문구는 `refundPolicy.ts` 정본 유지.

### 6.5 인증 화면
- 카드 폭 440, 로고 1회(내비 로고와 중복 금지 — AuthLayout은 상단 로고만), 제목은 화면 목적("로그인", "리스너로 가입").
- 소셜 버튼은 공급자 브랜드 가이드 준수(Google·Apple·Kakao·Naver·LINE 공식 스타일). **키만 넣으면 작동**하도록 구현하고, 키가 없는 공급자는 렌더하지 않음(작업지시 WI-A1).
- 비밀번호 규칙은 입력 중 실시간 체크리스트. 약관은 "전체 동의" + 필수/선택 개별 체크.
- 가입 완료 → 이메일 인증 안내 화면. 리스너는 인증 전에도 바로 듣기 가능(안내 배너 유지), 크리에이터·비즈니스는 인증 후 기능 사용. 인증 링크를 누르면 로그인 상태로 이어진다.
- 연령 확인(`AgeConfirmGate`)·필수 약관 재동의(`TermsConsentGate`)·관리자 TOTP 미등록 안내(2026-11-12 S-03)는 새 레이아웃에서도 그대로 동작해야 한다.

## 7. 범위 밖 (이번 패키지에서 하지 않음 — 별도 결정)
- 해외 결제(Stripe/Paddle 등 MoR)와 다중 통화: 다음 패키지. 이번에는 KRW 결제만, 표기만 현지화.

- 생성 AI의 공개 출시·학습·크레딧 결제: 이번에는 준비(Track G)만.
- 라이트 테마: 토큰 구조만 준비.

- 국가별 연령 기준 차등(태국·일본 등)은 현행 연령 확인 유지, 법률 확인 후 별도 반영.

## 8. 법적 문서 영향 (게시는 G-3)
이번 패키지로 **새로 수집·처리하는 정보**가 생기므로 개인정보처리방침·이용약관 개정안이 필요하다(작업지시 WI-L1, 초안만).
- 소셜 로그인 공급자 추가(Apple·Naver·LINE)와 공급자로부터 받는 항목.
- 이메일 인증, 사용자 언어 설정, 비즈니스 도입 문의(상호·연락처), 생성 AI 대기자 등록.
- 국외 이전 고지: Cloudflare 전 세계 엣지(SSR·캐시), LINE(일본) 등.
- 쿠키 없는 분석 방식 명시(제품 분석 이벤트).
- (Track G) 학습 참여 동의·생성물 권리 조항은 기능 출시 전 별도 개정.
